cocoonbox · Connect your agent

Console

Add cocoonbox to Claude Code, Codex or Cursor as one MCP server. The first time the agent connects, it opens your browser: sign in here and allow it. No token goes into its config.


    
The agent gets the box tools (shell, files, the desktop and the browser) and the box_* tools that create, wake and save boxes. A sleeping box wakes on the first tool call. Signed in this way, the agent works only in boxes it creates; until it has one, its box tools tell it to create one with box_create. You see and revoke it on the Agents page.

  


  

    
Claude Code

    
claude mcp add --transport http --scope user cocoonbox 

    
Then start claude, run /mcp, pick cocoonbox and sign in in the browser. Or sign in from your shell: claude mcp login cocoonbox.

  


  

    
Codex

    
codex mcp add cocoonbox --url 
codex mcp login cocoonbox

    
Or add it to ~/.codex/config.toml and then run codex mcp login cocoonbox. A longer tool_timeout_sec than the default 60 s lets desktop plans and scripts finish:

    
[mcp_servers.cocoonbox]
url = ""
tool_timeout_sec = 180

  


  

    
Cursor

    
Add to Cursor, or put it in ~/.cursor/mcp.json:

    
{
  "mcpServers": {
    "cocoonbox": {
      "url": ""
    }
  }
}

    
Then sign in to cocoonbox from Cursor's MCP settings when it asks. The Cursor CLI signs in with agent mcp login cocoonbox.
